# 转发记录阅读器（forward-reader）

让机器人真正**读懂别人转发的「合并转发聊天记录」**：收到就自动展开成普通消息，套娃转发一起展开，长记录读全，转发里的图片也能看。

## 它解决的具体问题

机器人内置其实已经会展开一次转发，但实测（读 `data/messages` 里的真实存档 + 直接打协议端）发现三种情况会翻车：

| 现象 | 根因（实测） | 本技能的做法 |
|---|---|---|
| 机器人回「我看不到转发内容」 | 展开失败时存档里只剩占位符 `[合并转发聊天记录]`；协议端对**负数 message_id** 常返回 `retcode 100`，但其实用消息段里的 64 位转发 `id` 就能读到（2026-11-01 实测，8 小时前的老转发也行） | 先用 `message_id`、失败自动改用转发 `id` 再取一次；**两条路都拿不到**时让模型照实说明原因（"这条转发的正文我这边取不到，重要内容麻烦直接贴文字"），并禁止它说"我打不开" |
| 转发里套着转发，里层看不到 | 内置刻意只展开一层，嵌套段变成占位符 | 用嵌套段里的 `id` 继续调 `get_forward_msg`（实测可行），默认钻 2 层、最多 3 层 |
| 长记录只看得到开头 | 内置上限：30 条 / 每行 200 字 / 共 3000 字 | 默认 60 条 / 每行 400 字 / 共 9000 字，超出会注明还差多少 |
| 图片只有 `[图片]` 占位 | 模型不知道转发里有哪些图 | 直接把图送给模型看（默认最多 3 张），同时把图片挂进消息存档，内置看图工具也能按需取 |

另外一个实测坑：**转发节点里的 QQ 号不可信**——协议端会把一层转发里所有人的 `user_id` 都填成同一个号（转发发起人），昵称却是各人各的。内置展开会拼出 `昵称(QQ:xxx)`，模型照着 @ 人会指错人。本技能只输出昵称，并在提示词里写明了原因。

## 怎么工作

```
别人发来合并转发
   │
   ├─ 程序内置的 ingest：先试着展开一次（可能失败/只展一层）
   │
   └─ 本技能 before-context 钩子（在提示词组装之前）
        ├─ 检查这条消息是不是"还没展开好"（占位符 / 被截断 / 套娃）
        ├─ 是 → 向本机协议端调 get_forward_msg（含递归钻套娃）
        ├─ 把完整文本写回消息存档（ctx.store.updateByMid）
        └─ 之后 before-llm-messages 再补一句说明（有几张图、失败时怎么写）
```

因为发生在**提示词组装之前**，模型看到的就是展开后的普通消息，由它自己判断要不要接话——不会额外触发一次回复，也不需要用户开口。

> 说明：技能钩子里拿不到 `ctx.onebot`（框架只给工具执行上下文），所以本技能直接向**本机协议端**发 HTTP。地址与 token 自动从 `data/config.json` 的 `snowluma` 段读取，只用于本机请求；设置页留了手填覆盖项。

## 工具

`forward_read`（模型侧看到的是 `forward-reader__forward_read`）

| 参数 | 说明 |
|---|---|
| `messageId` | 转发消息前的 `#数字`。省略 = 自动取最近一条转发 |
| `depth` | 套娃往下钻几层，1~3，默认用设置值 |
| `includeImages` | 是否把转发里的图片一起返回给模型看，默认按设置 |

给错 `#数字`（比如给成了一条引用消息）时，工具会改读它前面最近的一条转发，并在返回文本开头说明改了哪条；只有两条读取路径都失败时才让模型照实说取不到。

## 设置项

技能 → 转发记录阅读器 → 设置：

- **启用** / **收到转发时自动展开**（默认都开）
- **套娃展开几层**（默认 2）/ **最多展开几条**（60）/ **文本字数上限**（9000）
- **一次给机器人看几张图**（默认 3，填 0 = 不自动带图）
- **告诉机器人转发里有几张图**（默认开）
- **协议端地址 / Access Token**（一般不用填，留空自动读取）

## 文件

- `skill.json` —— 清单、设置项、提示词
- `index.js` —— 工具 + 两个钩子
- `lib/forward.js` —— 展开核心（递归钻套娃、图片收集、截断处理）
- `lib/bridge.js` —— 本机协议端 HTTP 调用（地址/token 解析）
